# @plugnmeet/docs-mcp

MCP server for the plugNmeet documentation. It reads `docs-index.json`, generated by
`plugins/docs-index-plugin` during the docs site build, and exposes the English and Spanish
docs/blog content to MCP clients.

- Streamable HTTP endpoint: `/mcp`
- Legacy SSE endpoint: `/sse` (plus `/sse/message`)
- Health check: `/` → `{ "ok": true, "service": "plugnmeet-docs-mcp" }`

## Tools

| Tool | Arguments | Purpose |
| --- | --- | --- |
| `search_docs` | `query`, `limit` (1-20, default 5), `section` (`docs`/`blog`), `locale` (`en`/`es`) | Ranked matches with title, URL, description and a body snippet |
| `list_docs` | `section`, `locale` | Every page grouped by category, with truncated descriptions |
| `get_docs_content` | `path` (site path or full URL), `locale` | Full markdown of one page plus its GitHub source link; falls back to suggestions on a miss |

The index is fetched once per isolate and cached in memory for 1 hour; if a refresh fails the
stale copy keeps being served.

## Local development

The server needs a built index. From the repository root:

```sh
pnpm build          # writes build/docs-index.json
pnpm serve --port 3010 --no-open
```

Then, in `mcp/`, point the worker at the locally served index:

```sh
pnpm dev -- --var DOCS_INDEX_URL:http://localhost:3010/docs-index.json
# Streamable HTTP: http://localhost:8787/mcp
# Health:          http://localhost:8787/
```

Unit tests (pure modules, no network) and type checking:

```sh
pnpm test
pnpm typecheck
```

## Going live

```sh
cd mcp
pnpm exec wrangler login    # once
pnpm exec wrangler deploy
```

The first deploy creates the proxied DNS record for `docs-mcp.plugnmeet.org` in the
`plugnmeet.org` zone (`routes` with `custom_domain: true` in `wrangler.jsonc`), so the server is
reachable at `https://docs-mcp.plugnmeet.org/mcp`. `workers_dev` stays enabled, so
`https://plugnmeet-docs-mcp.<your-subdomain>.workers.dev/mcp` remains available as a fallback.

Verify:

```sh
curl https://docs-mcp.plugnmeet.org/      # must return {"ok":true,...}
```

If a Cloudflare challenge/interstitial page comes back instead, add a WAF skip rule
(Security → WAF → custom rules → Skip) with the expression
`http.host eq "docs-mcp.plugnmeet.org"` — headless MCP clients cannot solve challenges.

`DOCS_INDEX_URL` in `wrangler.jsonc` points at `https://www.plugnmeet.org/docs-index.json`.
That file only exists once the docs site is deployed with the index plugin; until then the tools
return the "index not available" message.

## Client setup

Claude (custom connector): add `https://docs-mcp.plugnmeet.org/mcp` as a remote MCP server URL
(use `https://plugnmeet-docs-mcp.<your-subdomain>.workers.dev/mcp` while the custom domain is
not live yet).

Cursor / VS Code (`mcp.json`):

```json
{
  "mcpServers": {
    "plugnmeet-docs": {
      "url": "https://docs-mcp.plugnmeet.org/mcp"
    }
  }
}
```

Clients that only speak stdio can bridge to the remote endpoint:

```json
{
  "mcpServers": {
    "plugnmeet-docs": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://docs-mcp.plugnmeet.org/mcp"]
    }
  }
}
```

## Notes

- Built on `McpAgent` from `agents/mcp`, which requires the `MCP_OBJECT` Durable Object binding
  and the `v1` migration. Upstream marks `McpAgent` as feature-frozen in favour of the stateless
  `createMcpHandler`; the tools themselves are transport-agnostic and can be moved later.
- `@modelcontextprotocol/server` is installed explicitly because `agents/mcp` imports it while
  listing it only as an optional peer dependency.
